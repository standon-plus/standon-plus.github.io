Project 1: Colorizing the Prokudin-Gorskii Photo Collection

Overview

In the early 1900s, a Russian chemist and photographer called Sergei Prokudin-Gorskii envisioned a future of color photography. To realize his goal, he traveled around the Russian Empire with special permission from the Tsar Nicholas II, and took thousands of three-filter photographs (one photographic plate per color of RGB). While these photos were rarely rendered in the years afterwards, the Library of Congress' modern digital scans of these plates enable high-quality reproductions of Prokudin-Gorskii's color images. In this project, I will be using rudimentary image processing techniques to create my own reproductions of images in this collection.

The general strategy for this algorithm is to align the three photographic plates, assign the pixel values of each plate to a corresponding color channel, and stack them to create a typical (H, W, 3) RGB image. If this is not done correctly, we get an artifact called Lateral Chromatic Aberration (LCA). This is a fancy term for RGB channel misalignment, and it creates an effect where the image seems to have multiple copies, or some fringing artifacts on the edges. Single-scale Alignment

A naive way to get aligned images is by holding one channel constant. Then, for each other channel, we search over a pre-determined range of values (say -15 to 15) of shifts in the row and column directions, and choose the transformation that gives the best alignment (compared to the fixed channel). To score the alignment, there's a number of image distance metrics we can choose. One option is the Euclidean distance (L2 norm), which computes the Frobenius norm of the difference between the two images. Another option is the normalized cross-correlation (NCC), which finds the dot product between the normalized, demeaned versions of each image. Coming from a signal processing background, I'll be preferring NCC over L2 since it seems more natural to me.

Initially, I calculated my distance metric using as much of the image as possible, only cropping out the parts that wrap around in np.roll. However, this led to misalignment issues in monastery. I found out that this is due to the exterior frame: the border intensity values are quite large (either white and close to 1 or black and close to 0), which messes up the score. Instead, I ensured that I'd only use image pixels by cropping a consistent 10% off of the sides of each image. This greatly helped the LCA effect in monastery.

Multi-scale Alignment

Single assignment seems to work great for small images, but there's a critical problem. Once the image size gets larger, the shift required to align these channels increases—to around values of plus or minus 100—in order to search over a similar percentage of the image. Not only does a larger image mean a slower calculation of the NCC, but also we'd have to search over a much wider range of shifts (around 200x200=40000 in total!) This would make the algorithm extremely slow. To combat this effect, we can use the strategy of the image pyramid. Instead of searching explicitly over the whole, large image, we downscale the image until it gets to a reasonable size. Then, we search more exhaustively over this smaller image, save the best shift, and apply an equivalent shift to a slightly upscaled version of the image. As a result, we can search less intensely on the upscaled version, since we know we've gotten in the ballpark estimate with the downscaled image. This process can be done over and over, increasing the image size and decreasing the search window, in order to align any size of image relatively fast.

To downscale the images, I used skimage's rescale function as suggested by the starter code. This function implements a Gaussian blur to prevent anti-aliasing before downsampling. Without this blur, finer details in the image would be misrepresented, for example with jagged edges or other unwanted patterns. So, this anti-aliasing ensures that the downscaled image metrics for a certain shift are as close as possible to the respective upscaled image metrics.

I implemented an iterative version of the image pyramid-based multiscaling, with editable values of scale factor (I used 0.5), "small enough" image size for the exhaustive search (I used 500x500), and shift ranges (I started with +/- 15 for the exhaustive search, and went with +/- 10 for the other searches). I found that these values gave a good balance of speed while finding accurate shifts where possible with this version of the method. None of the images took longer than 45 seconds to render.

Failure Modes

In some of the images (specifically the Emir of Bukhara), I ended up failing the alignment. Although the alignment is relatively close, there is still clear LCA. I believe this is because of the large differences in brightness between channels. For example, the blue robe the emir has very different visible features and overall intensity in the blue channel compared to its features in the green or red channels. This would mean the NCC gives a nonrepresentative view of whether or not the two channels are truly aligned.
