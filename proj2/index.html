Overview

In this project, I'll be using convolution and traditional image processing methods to do some cool things with images, like finding edges, creating hybrid images, and blending 2 images together!

Part 1: Fun with Filters

Convolutions from Scratch

Convolution is one of the essential operations I'll be needing for the rest of this project, so it'll help my understanding to implement convolution on images from scratch. I implemented it with both a 4-loop (iterating over the image and then the filter, then adding to the result) and a 2-loop (iterating over just the image itself and doing a dot product between the image and kernel at that point).

Following the lead of scipy.signal.convolve2d, I also implemented the 'same', 'full', and 'valid' options. To do this, I added enough padding to the image (adding 0s) before convolving so that I calculated every time the filter overlapped at least 1 pixel with the image. Then, I got rid of the parts I wouldn't need to include in the 'same' and 'valid' versions of the convolution. However, by default I keep the 'full' level of padding. This implementation allowed me to reuse the maximum amount of code, since I just had an if statement telling me how much I needed to slice out after the main computation is completed.

Here are my implementations:

def convolve_4loops(in1, in2, mode='full'):
    m, n = in1.shape
    u, v = in2.shape

    assert u < m and v < n, "Ensure kernel is the second input"

    in2 = in2[::-1, ::-1]

    # Make out array and add padding to in1
    pad_x = (u - 1) // 2
    pad_y = (v - 1) // 2
    out = np.zeros((m + u - 1, n + v - 1))
    in1 = np.pad(in1, ((u - 1, u - 1), (v - 1, v - 1)))

    for i in np.arange(out.shape[0]):
        for j in np.arange(out.shape[1]):
            for x in np.arange(u):
                for y in np.arange(v):
                    out[i, j] += in1[i + x, j + y] * in2[x, y]

    if mode == 'valid':
        out = out[u - 1:-(u - 1), v - 1:-(v - 1)]
    elif mode == 'same':
        rem_x = u - 1 - pad_x
        rem_y = v - 1 - pad_y
        out = out[pad_x:-rem_x, pad_y:-rem_y]
    return out

def convolve_2loops(in1, in2, mode='full', boundary='fill', fillvalue=0):
    m, n = in1.shape
    u, v = in2.shape

    assert u < m and v < n, "Ensure kernel is the second input"

    in2 = in2[::-1, ::-1]

    # Make out array and add padding to in1
    pad_x = (u - 1) // 2
    pad_y = (v - 1) // 2
    out = np.zeros((m + u - 1, n + v - 1))
    in1 = np.pad(in1, ((u - 1, u - 1), (v - 1, v - 1)))

    for i in np.arange(out.shape[0]):
        for j in np.arange(out.shape[1]):
            sub = in1[i:i + u, j:j + v]
            out[i, j] = np.sum(sub * in2)

    if mode == 'valid':
        out = out[u - 1:-(u - 1), v - 1:-(v - 1)]
    elif mode == 'same':
        rem_x = u - 1 - pad_x
        rem_y = v - 1 - pad_y
        out = out[pad_x:-rem_x, pad_y:-rem_y]
    return out

Finite Difference Operators

Let's use convolution to detect edges now! We can create the finite partial derivative operators Dx=[1, 0, -1] and Dy=Dx.T, which give us vertical and horizontal edges respectively. However, these two filters only get us directional edges. What if we want to highlight edges of any direction equally? To get around this, we combine the results of these 2 in quadrature to get a "gradient magnitude" image, which is essentially a general edge detector — edges of any direction will return a positive result.

Now I'll use a threshold on this gradient magnitude image to determine what's a "sharp enough" edge. Empirically, after some tweaking, I found a good level for this threshold is 0.25. To get my threshold, I was looking for full coverage of the man and his camera where possible — the "edges" detected from the grass was noise in my eyes, and I wanted to minimize the random speckle in the final edge detector. Derivative of Gaussian Filter

Using this raw method to find edges, I saw a lot of noisy detections from the grass, etc. These are high-frequency features, so if we get rid of some of these, could we get a more robust edge detector? Let's use a Gaussian filter to do this! The Gaussian filter is similar to a box filter in that it acts as a low-pass filter and gets rid of higher frequencies in the image. Here's an example:

We can tweak the cutoff frequency by modifying the standard deviation, sigma, of the distribution, which we'll utilize in later parts. A higher sigma blurs the image more than a smaller sigma. Intuitively, this makes sense since a Gaussian distribution with small enough sigma essentially gives back a delta function/identity. If we blur the image before trying to detect images like above, we can see more success without having to worry as much about noise in the result. To reflect this, it turns out we can have a lower threshold to get a similar edge result — in this case, about 0.15 sufficed.

It turns out that instead of doing a blur then finding the edges afterwards, we can convolve the Gaussian filter with our edge detector directly to give us a more robust edge detector all in one shot. This new filter is called the derivative of Gaussian (DoG) filter, and here's what it looks like!

If we use these DoG filters to create our robust edge detector, it ends up looking exactly the same (as we expected). You can also see how this method lets us gets rid of a lot of the noise from our naive edge detector using the raw finite difference operators.

Part 2: Fun with Frequencies

Image Sharpening

Let's try to sharpen some images! I'll be doing these using the "unsharp" filter, which is a misnomer.

To make the filter, we first need to extract out some high-frequency information from the image. We can do this by subtracting the original image with a Gaussian blurred version of the original filter. Intuitively, since the Gaussian blur is a low-pass filter, the remainder acts like a high pass filter. Then, we can add some of these high-frequency features back into the image. To formalize this, the full unsharp filter is in the form 1 + a(1 - G) = (1 + a) - aG, where G is the Gaussian filter, 1 is the identity, and a is the sharpening factor. In the Taj photo, you can see that edges around the gate and on the edges of the Taj Mahal gets blown out more and more as the alpha value increases. When trying to re-create my original sharp image using the unsharp filter, results are varied. For too low of an alpha, the image still seems blurred, and for too high of an alpha, the image looks extremely blown out (e.g. the rocks have very sharp transition with the grass). In all cases, the sharp, non-blurred image looks the best, because low-pass filtering inherently gets rid of some information about the image that cannot be brought back.

Hybrid Images

Let's create some hybrid images! These images look like one image up close, but look like another image from far away. We can do this by exploiting low frequencies and high frequencies. Since from far away, low frequencies dominate, and vice versa from up close, we can low-pass (Gaussian filter) one image and high-pass (identity minus Gaussian filter) the other, then add them together to get a hybrid image. The trick mainly here is to align the general features of each image so each side looks relatively plausible. To do this, I used pre-written code to align images by selecting 2 points on each image that should line up. Afterwards, I did some post-processing by trimming the images so that the black edges didn't show (or didn't show as much as realistically possible). I also had to introduce a scaling factor that I called alpha, since some high-frequency details were stronger than others. I'll note the alpha values I used as I go.

For the cutoff frequency, I used differing values of sigma in the Gaussian filter: 5 for the low-pass and 2 for the high-pass. Since sigma=5 is a quite strong low-pass filter, while sigma=2 means my high-pass filter is getting rid of some relatively high frequencies, I end up filtering out a middle section of the frequencies of both images. This makes for a better hybrid image since the distinction between the far image and the close image is more readily visible/has less transition.

Gaussian and Laplacian Stacks

For the next part of this project, I'll be doing multi-resolution blending, but first I need to introduce the idea of a Gaussian and Laplacian stack. Intuitively, the Gaussian stack represents increasingly lower and lower-pass filtering, with different cutoff frequencies. As you go down the stack, the cutoff frequency should get lower and lower, and represent only low-frequency features. The Laplacian stack is the difference between two consecutive layers of the Gaussian stack. Due to the Gaussian stack's construction, the Laplacian stack actually represents a band-pass filter! At each level of the Laplacian stack, we only keep frequencies within a certain range, depending on how your cutoff frequency changes between stacks. The last layer of the Laplacian stack generally keeps the last layer of the Gaussian stack (absolute lowest-frequency features), so that a sum across the layers of a Laplacian stack will give back the original image.

For this implementation, it turns out we need a Laplacian stack with roughly an octave (doubling) of frequencies within a stack. To keep slightly more detail than this and get better empirical image quality, I use a Gaussian stack that exponentially decreases in cutoff frequency by the square root of 2 (about 1.414) each layer.

Multi-Resolution Blending

Now let's implement multi-resolution blending! For this, we'll need a mask which tells us when we want image 1 and when we want image 2. Then we construct a Laplacian stack of the blended image. At each level, we use the Gaussian stack level of the mask, and add together the Laplacian stack levels of the 2 individual images. Then, to form the final blended image, I sum the elements of the Laplacian stack.
